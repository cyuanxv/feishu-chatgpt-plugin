# 真实接通前的下一步

当前是可审查的开源开发稿。云端已有可运行的 synthetic MCP、17 条只读路由和离线 SDK/数据库/安全测试；尚未连接真实飞书、安装到 ChatGPT、部署生产服务或申请官方目录。不是“只差一个密钥”。

## 现在只需确认两件事

1. 是否有可管理的飞书测试企业，准备使用飞书还是 Lark，以及是否已有企业自建应用。可以提供应用名称/App ID 等非秘密标识，不要发送 App Secret、授权码、token 或密钥截图
2. 选择获准使用的云端 Node.js + PostgreSQL 托管及 HTTPS 域名。若需要新付费资源，先确认服务商、价格和账单承担方，再创建

## 开发侧仍需完成

- 为真实身份认证/同意流程接入生产 MCP OAuth 授权服务和持久化 grant，不能把 mock broker 上线，也不能把内部 router 的 context 校验当作登录
- 核实飞书授权入口与完整 PKCE/刷新约束，完成真实回调/账户绑定/撤销路径；现有 SDK token 交换原语不等于完整 OAuth 流程
- 对每个实际启用端点补齐最小 provider scope 与实际授权结果校验。代码里的 `docs.read` 等是内部权限，不能直接当成飞书权限提交
- 在选定 PostgreSQL 上验证并发刷新、断开/重新连接、迁移、最小数据库角色与密钥轮换；PGlite 单连接结果不能代替它
- 完成域特定输出约束、运行/错误预算、已明确不支持的过滤条件和部署运维。之后再接真实 HTTP，保留独立生产启用门禁

## 需要用户亲自批准或安全配置

- 创建应用/授权或扩大持久访问、开启应用能力与管理员审批，按实际页面逐项确认最小权限
- App Secret、数据库凭据和加密密钥由用户在批准的云端安全设置中输入和提交；不进聊天、仓库、截图或测试 fixtures
- 若出现新的法律条款或费用，先提供条款链接/具体金额，由用户决定

## 接通后的验收顺序

专用测试账户和合成测试资料 → 真实只读 API → 真实用户 OAuth 往返 → 多账户/跨企业隔离与撤销 → 原生 PostgreSQL 并发 → ChatGPT 实际安装和工具路由 → 评审后只读上线。十三项写工具仍保持关闭，不能以只读通过替代写操作确认、幂等与取消验收。

## 官方收录

[OpenAI 插件准入规则](https://developers.openai.com/plugins/plugin-guidelines) 对主要充当非官方第三方连接器的插件有限制；开源、具备 OAuth 或增加工作流都不自动消除该限制。先核实资格/服务商授权，再准备 [官方提交材料](https://developers.openai.com/plugins/deploy/submission)：发布者验证、稳定远程端点、官网/支持/隐私/条款页面、图标演示、专用审核账户和测试案例。未提交，也不保证审核通过。
